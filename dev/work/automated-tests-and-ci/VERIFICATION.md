## Current repository and CI baseline

- `src/ScriptSyncPilot.slnx` contains the Common, FunscriptEditor, and HandySync applications/libraries and two test projects: `ScriptSyncPilot.Common.Tests` and `ScriptSyncPilot.FunscriptEditor.Tests`.

- The FunscriptEditor suite includes WinForms tests and shared Handy HTTP/lifecycle tests; it references both HandySync and FunscriptEditor.
- `.github/workflows/windows-release-verification.yml` checks out the repository, sets up .NET 10, restores `src/ScriptSyncPilot.slnx`, builds Release, and runs all solution tests with a 2-minute hang timeout. Pull requests to `main` trigger when `src/**` or `.github/workflows/**` changes; pushes to `main` and manual dispatch are also triggers. The solution, projects, and tests (including `src/tests/**`) are all under `src/`.
- The archived release verification records a clean-checkout GitHub Actions run: restore/build/test passed, with 341/341 tests at that revision (90 Common and 251 FunscriptEditor). This is historical evidence for that commit, not a current run for every later revision.
- Later local full-suite evidence is recorded in work-specific verification notes, including 345 passing tests after the fine-horizontal-navigation changes. It does not itself prove a clean-checkout CI run for this work item.

## M2.2 — mpv attach, observations, cancellation, and disposal

- `MpvSessionTests.Attach_ConnectionTimeoutReportsPipePathAndReleasesPipe` verifies a missing local pipe is surfaced as an actionable `IOException` and the failed client pipe is released.
- `MpvSessionTests.Attach_ConnectCancellationReleasesPendingPipe` cancels an attach while it is waiting to connect and verifies the pending client pipe is released. `Attach_PreCancelledTokenDoesNotConnect` also covers cancellation before connection starts.
- Existing named-pipe server tests verify subscription commands and observable position, pause, duration, and speed state/events; malformed speed observations preserve state while the reader continues.
- `MpvSessionTests.Dispose_StopsPropertyObservationWithoutDisconnectNotification` verifies state was observed before disposal, disposal ends the local pipe reader without reporting a remote disconnect, repeated disposal is safe, and subsequent commands fail as disconnected.
- Existing `LifetimeCancellation_EndsObservationWithoutHanging` verifies cancellation of an attached session's observation lifetime raises the disconnect notification.
- `Attach_CancellationDuringPropertySubscriptionsDoesNotReportRemoteDisconnect` cancels after the local server receives the first observe command, checks cancellation and pipe cleanup, and confirms failed local setup does not emit a remote-disconnect notification. The reader loop now awaits the attach outcome; only a successfully attached session reports its reader ending as a disconnect.
- Fix: `MpvSession.AttachAsync` now closes and clears the pipe on connect timeout, cancellation, or subscription-write failure. `Dispose` is idempotent and releases the pipe and read cancellation source.

These are local named-pipe tests and do not launch mpv or require Handy hardware. A 5-second named-pipe connect timeout is intentionally exercised by the missing-server case.

## M2.3 — session replacement and stale notifications

- `MpvSessionReplacementTests.Editor_DropsQueuedNotificationsAfterSessionReplacement` queues position, pause, duration, speed, and disconnect callbacks for an old session in the FunscriptEditor form's WinForms queue, replaces the active session before dispatch, and asserts the playhead, duration, controls, labels, and active session are unchanged.
- `MpvSessionReplacementTests.HandySync_DropsQueuedNotificationsAfterSessionReplacement` queues position, duration, speed, and disconnect callbacks for an old session in HandySync, replaces the active session before dispatch, and asserts waveform state, status, attached state, and active session remain unchanged.
- HandySync's disconnect subscription now delegates through `OnMpvDisconnected`, so the active-session identity is checked again when its queued UI callback runs, matching the replacement guard in the editor form.
- These are deterministic WinForms callback-queue tests, not end-to-end attach/detach tests. Archived command-ordering tests separately cover fake-HTTP device commands queued or completing across replacement.

## M2.4 — Handy script setup and teardown ordering

- `HandyScriptSetupOrderingTests.ScriptSelectionChangesDuringUpload_OnlySetsUpLatestSelectedScript` uses the form's actual `LoadScript` path while the fake hosting upload is blocked. After a new file is selected, the stale upload response is discarded without HSSP setup; the new CSV is uploaded and only its URL is configured.
- `HandyScriptSetupOrderingTests.ScriptSelectionChangesDuringSetup_StopsOldSetupBeforeInstallingLatestScript` changes the selected file while the first fake HSSP setup is blocked. Once the old setup completes, the installer stops it, uploads the new file, and sets up its URL; final installed client/version match the selected script.
- Existing `DeviceControlPollingTests.DisconnectCancelsInflightPlayAndSkipsQueuedSeekBeforeStop`, `DisconnectDrainHasHardDeadlineAndRetainsClientUntilLateWorkCompletes`, and `DisconnectStopThatIgnoresCancellationRemainsPendingUntilDeferredTeardownReleasesGate` provide deterministic fake-transport drain/stop/disposal ordering. These tests were rerun with the new selection-race tests.
- No product defect was found in the script-selection race; the current version loop and post-upload identity/version checks behave as intended.

## M2.5 — timeline limits, deletion during drag, and keyboard routing

- `NumericPositionEntryTests.ZoomAndScroll_StayWithinDurationAndViewportBounds` checks zoom-in/out clamps at the absolute and duration-derived limits, zoom reclamping after duration changes, and scrollbar values remaining in `[Minimum, Maximum - LargeChange]` at both viewport edges.
- `NumericPositionEntryTests.DeleteDuringActionDrag_EndsDragAndCannotMutateNextAction` moves a selected action, deletes it while the mouse drag is active, then sends another move/up pair and verifies the remaining action is unchanged.
- `NumericPositionEntryTests.Routing_UnfocusedTimelineDoesNotConsumePositionKey` complements existing physical-key decoder and focused preprocessing tests by checking an unfocused timeline leaves the script untouched. Existing coverage also verifies focused numeric and Space routing, repeats, modifiers, navigation keys, and numpad exclusions.
- These tests exposed no product defect; no behavior change was needed.

## Limitations

- Root-level .NET build/restore configuration files do not exist in this checkout. If such files are introduced, the PR path filter must be extended to include them.
- The recorded CI run proves only the exact source revision shown in the run table; future commits and a merge result need their own successful checks.
- Reused tests do not prove behavior beyond their asserted conditions. The named test and archive boundaries above are part of the M1.1 audit; direct attach/detach transition coverage remains a possible gap.
- No real Handy hardware or external mpv service is required for the acceptance tests; simulated results must not be described as hardware certification.
- The recorded clean-checkout runs verify their exact source revisions; they do not certify real Handy hardware, a live mpv process, or a merge result after future changes. Existing testing also does not exercise the full UI attach/detach transition end to end.
