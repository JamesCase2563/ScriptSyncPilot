# Error Message Inventory

**Status:** M1.3 characterized from current HandySync source and existing tests on 2026-11-02. This records present behavior; it does not approve message quality or claim uncovered failures are safe.

API errors below refer to `HandyApiClient`'s normalized messages: `<operation> failed: <HTTP status>.`, `<operation>: HTTP transport failed[ (<status>)].`, `<operation>: transport I/O failed.`, `<operation>: invalid JSON response.`, `<operation>: invalid response shape.`, `<operation>: response did not contain a result.`, or `<operation>: device error[ <code>].` Response bodies and untrusted device error names/messages are omitted. Timeouts use `<operation>: request timed out.` Raw mpv/filesystem exception messages are passed through by some form handlers; those need the safety review called out below.

## Characterization boundaries

- `Log` sends messages to both the visible log textbox and persistent `AppLog`; `SetStatus` updates the status label. Some paths only log and leave the status label unchanged.
- The most material uncovered cases are ordinary non-timeout form-level Handy failures, actual offset/stroke write failures, mpv attach/video command failures, repeated temperature-read failure state, and raw local path details in filesystem/mpv exceptions.
- The archived credential and timeout records provide the specific evidence linked above. This inventory is not a new test run and does not claim that an untested case passes.
