The old controller documents contain a few useful ideas, but the separate ControllerHost/Core architecture doesn’t need to survive.

**Worth Keeping**
- **HandySync: reconnect and recovery.** Restore device setup and resume from the current mpv position without restarting the video. Already covered in its improvement notes.
- **HandySync: firmware and capability checks.** Validate device compatibility before synchronization. Also already documented.
- **HandySync: command ordering and safe shutdown.** Existing implementation now addresses much of this; keep these as architectural requirements rather than untouched backlog tasks.
- **HandySync: diagnostics and latency handling.** Preserve useful request timing, clock-offset diagnostics, and offset adjustment. Avoid carrying over a separate local scheduler unless a future backend requires it.
- **HandySync: optional Buttplug/Intiface backend.** Keep as a future alternative, not an obligation to introduce ControllerHost.
- **Both applications: separation of UI and session logic.** Worth retaining as a design direction when lifecycle complexity warrants extracting services.
- **Both applications: focused tests and CI.** Especially script round-tripping, session replacement, command ordering, and shutdown.
- **Both applications: privacy-conscious logging.** Never log connection keys or authentication credentials.

**Not Worth Carrying Forward**
- A separate ControllerHost with adapter registration, device registry, and mandatory controller-proxy APIs.
- WPF GUI scaffolding and fixed implementation timelines.
- Headless/service hosting and REST/WebSocket control APIs without a current use case.
- Generic BLE/TCP integrations and unrelated sensor adapters.
- Project-creation tasks for nonexistent Core/ControllerHost projects.

There’s little editor-specific material in the controller documents themselves. Editor ideas belong primarily to the old platform spec: undo/redo, snapping, markers, and possibly multitrack editing, each evaluated independently.

My recommendation: remove the four controller documents, retain the relevant requirements in current architecture docs, and avoid duplicating ideas already present in HandySync’s backlog. No files changed yet.
