> Historical discussion note. The agreed `work/` and `archive/` convention is maintained in [dev/README.md](../dev/README.md); that document supersedes the recommendations here.

Use one folder per feature/change under `dev/work/`, regardless of affected projects, to distinguish feature work from the actual .NET projects.

```text
dev/
  FunscriptEditor/
    ARCHITECTURE.md
    BACKLOG.md
  work/
    pattern-insertion/
      PLAN.md
      DESIGN.md
      VERIFICATION.md
  archive/
    2026-10-pattern-insertion/
      PLAN.md
      DESIGN.md
      VERIFICATION.md
```

Keep it lightweight:
- **PLAN.md:** scope, affected projects, decisions still needed, milestones, task checklist, and status.
- **DESIGN.md:** implementation details when substantial enough to deserve a separate document.
- **VERIFICATION.md:** acceptance criteria, test results, and unresolved limitations.
- Add research or experiment notes only when useful.

When the work finishes:
1. Update the permanent architecture documentation with the implemented design.
2. Move remaining ideas into the project backlog.
3. Record the outcome and PR reference in the plan.
4. Move the entire work folder into `dev/archive/YYYY-MM-<name>/` and update links.

Archived documents are historical snapshots, not maintained instructions. Permanent docs should explain the current system without requiring readers to consult archives.

Use `dev/work/` and `dev/archive/` for all work, including work confined to one project. Record affected projects in the plan; keep permanent architecture and backlog documents in their project directories.

The earlier `plans/` suggestion is superseded by `work/`, using one work folder per feature/change rather than per release or PR.
