I've made all three changes; the editor builds cleanly, but I haven't run the app to try the new window or the layout fix. It wasn't a big change, so I implemented it now.

**Insert Pattern no longer blocks the editor** (`PatternInsertionDialog.cs`, `MainForm.cs`)
- The window stays open while you play, seek and step the video. Choosing Edit > Insert Pattern again brings the open window to the front.
- Moving the playhead never changes the times you've entered.
- Insert rebuilds the pattern from the current script, so edits you make after previewing aren't overwritten.
- After a successful insert the window closes. If you Stop or cancel on the conflict prompt, it stays open.
- "Cancel" is now "Close".

**Start/end times instead of a length**
- There are now four time fields: observation start/end and output start/end. Each takes milliseconds (3 decimals) and has a **From playhead** button.
- The observation span is end − start, and the pattern now starts at the output start rather than the playhead.
- When the window opens, the fields default to the playhead, the playhead + 30 s for the observation end, and the playhead + 12 s for the output end.
- If an end is not after its start, you get a clear message instead of an error.

**Label alignment**
- The input area was stretching to fill the window, so its last row ("Maximum section") grew taller than the others and the label drifted away from its box. That area now only takes the height it needs, and each label and box are centred on the same line.
- The window is a bit larger to fit the extra buttons.

I also updated the pattern-insertion docs (`DESIGN.md`, `PLAN.md`, `VERIFICATION.md`, and `ARCHITECTURE.md`) to describe the new window and inputs. That includes two new manual checks: using the video while the window is open, and editing the script before Insert.
